# 全市场扫描：现在哪只是「穿越周期的龙」

回答「找一下现在市场上哪只股是穿越周期的龙」用的是**扫描**，不是逐只事后判。
本文件是口径 + 配方 + 定性分类；脚本见 `scripts/screen_cycle_crossing.py`。

## 一、口径（先回述给用户，别默认对方知道）

| 项 | 口径 |
|---|---|
| 区间 | 至少 3 个月（约 60-80 个交易日）。少于 40 个交易日看不到完整的两段周期，穿越次数会被系统性低估 |
| 涨停判定 | 分板块阈值：主板 ≥9.7%、创业板/科创板（300/301/688/689）≥19.7%、北交所 ≥29.7% |
| 剔除 | 次新（`list_date` 落在区间内或区间前 3 个月内）。新股连板是发行制度产物，不是穿越 |
| 穿越次数（可算定义） | 收盘价从区间高点回撤 **≥15%** 之后，**重新创出收盘新高**记 1 次。要求「死过又活过来」，不接受单纯波动 |
| 存活过滤 | 最新收盘距区间最高收盘 **> -5%**，且收盘在 **MA10 上方** |
| 换手 | 用 `daily_basic.turnover_rate_f`（自由流通换手）。情绪龙常态 35%-60%，**不构成否决** |

实测校准（一次约 3.5 个月 / 74 个交易日的扫描）：8445 条涨停记录 → 涨停 ≥6 天的非次新 178 只 →
同时满足「死过 ≥15% + 重新创新高 + 现在 MA10 上方且距高点 ≤5%」的**只有个位数**。
如果筛出来是几十只，几乎一定是漏了前置门（身份 / 死亡考验），不是市场突然遍地穿越龙。

## 二、配方（四步，全部可复现）

### Step 0 建缓存（每区间一次，之后秒出）

```python
cal = pro.trade_cal(exchange='SSE', start_date=s, end_date=e, is_open='1')
for dd in sorted(cal.cal_date):
    pro.limit_list_d(trade_date=dd)      # 必须逐日；整段拉会在 6000 行截断
    pro.daily(trade_date=dd)             # 全市场面板
    pro.daily_basic(trade_date=dd, fields='ts_code,trade_date,turnover_rate_f,circ_mv,pe_ttm')
```

存 `~/.hermes/cache/limitpool/`：涨停池 CSV（`to_csv`）、面板 `to_pickle`（本机无 pyarrow）。

### Step 1 候选池

- 每股聚合：涨停天数（`trade_date.nunique()`，只取 `limit=='U'`）、首板日、末板日、`limit_times` 最大值；
- 过滤：涨停天数 ≥6，排除次新；
- 想要「跨周期」而不是「本月妖股」，再叠一条**跨月**条件（区间首月与末月都有涨停）。

### Step 2 穿越计数（收盘价序列上跑，别用涨停池）

```python
cross = 0; cur_peak = s.iloc[0]; deep = False
for dt, px in s.items():
    if px / cur_peak - 1 <= -0.15: deep = True      # 死过一次
    if px > cur_peak:
        if deep: cross += 1; deep = False            # 活过来并创新高
        cur_peak = px
```

`cross >= 1` 才是穿越过；`cross >= 2` 是多次穿越（需要逐次列事件，不能只报次数）。

### Step 3 逐只定性（这一步必须人工，无法自动）

对 `cross>=1` 且通过存活过滤的头部候选，逐只打印：

1. **涨停日序列**（至少 35 个交易日，标 `Z`），看清每一波的起止、断板日、回撤幅度；
2. **断板日最高价**与之后是否放量突破它；
3. **峰量比**：区间最大成交额 = 首波峰量，调整期成交额 / 峰量（1/3 以内才算缩量到位）；
4. **自由流通换手**与流通市值（`circ_mv`/1e4 得亿元）；
5. **`kpl_list`** 的 `lu_desc` / `theme` / `status` 序列——标签漂移＝人气合力，不是板块；
6. **`top_list` / `top_inst`**：断板天量日谁在买谁在卖；
7. **`disclosure_date`** 预约披露日 + 中报/季报同比 + 解禁（`share_float`）。

## 三、四类定性（每只候选必须归到其中一类）

| 类型 | 判据 | 怎么写 |
|---|---|---|
| **真穿越** | 前置门（身份 + 回撤 ≥15%）过，缩量到位后放量吃掉断板日最高价，现在 MA10 上方 | 「唯一一只真穿越」+ 逐次列事件 |
| **没断气的强龙** | 六连板→断板→只横盘回撤 2%-5%→二次加速创新高 | 明确写「更强但不算穿越，位置更高」；换手 ≥50% + 财报临近就直接不建议新开 |
| **穿越进行中** | 反包二板已成立，但收盘仍在前高之下 | 「差一个涨停才算成立」，并写出那个价位 |
| **穿越过、已在派发** | 历史穿越次数 ≥1，但现在跌破 MA5、缩量不足、放量滞涨/长上影 | 归到「反面/已结束」栏，不能当买点推荐 |

**最容易犯的错是把第 2、3 类说成第 1 类**：横盘不深就再涨的（第 2 类）没有死亡考验；
反包二板但没吃掉前高的（第 3 类）确认还差一步。两者都会被误报成「穿越买点」。

## 四、输出结构

1. **先给唯一答案**（一只），再给 2-3 只备选并标注它们属于上表哪一类；
2. 每只给：穿越事件时间线（断板日 / 回撤幅度 / 复活方式）→ 现在的位置（距高点、距 MA10、换手、峰量比）→ 谁在场（席位性质）→ 事件日历；
3. **必须补一段市场结构**：当日最高板是否唯一、并列几只、涨跌停家数、昨涨停溢价中位。
   最高板并列 → 新周期还在启动段，穿越龙是孤票、没有板块接力，仓位上限按这一条下调；
4. 收尾：不碰清单 + 数据口径说明（当日涨停池若未入库，写明板数由 `daily` 自算、席位待补）+ 免责。

## 五、陷阱

- **只看涨停池会漏掉「一字板型」穿越**：缩量一字（换手 2%-3%）在涨停池里和放量板长得一样，必须回到 `daily` 看 open/high/low 与成交额才能区分「买得进」还是「买不进」。
- **穿越次数对低流动性小票天然偏高**：来回 15% 波动太容易。所以身份门（曾是唯一最高标）不能省，否则筛出来的是一堆没人接的壳。
- **「距最高收盘 0.0%」的同一天会挤出一堆票**：那说明当天是普涨日，不是它们都是龙——按 `cross` 与板数排序，别按距高点排。
- **当日 18:00 前 `limit_list_d` 是空表**：当日板数用「前一日 `limit_list_d.limit_times` + 1」重建，个股涨幅按板块阈值从 `daily` 自算；龙虎榜当日不可得，要写明。
